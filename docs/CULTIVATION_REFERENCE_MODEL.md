# 栽培マスターと現在の見通し

## 役割

- 圃場の品種・実際の田植日を入口とし、品種共通の平均的な日数と過去の実測履歴を参考にする。
- 現在の見通しはマスター編集後に再計算する。実際の幼穂確認日・出穂確認日・田植日や、過去に保存した予測は書き換えない。
- 生育ステージの手動選択は観察者の判断であり、出穂確認を記録したことにはしない。
- 振り返りの年間タイムラインには推定日を実績として追加しない。

## 日数の参考計算

今年の実測を優先する。履歴は当時の品種を確認できるものだけを集計し、同じ圃場・品種を優先、なければ同品種の他圃場を参照する。圃場・年ごとの最初の該当実測を用い、各年の平均を同じ重みで扱う。

品種マスターと履歴平均がある場合、暫定的に両者を半分ずつ参照する。これはアプリ内の説明可能な参考計算であり、農学的に検証済みの予測モデルではない。表示する日付幅も統計的な信頼区間ではない。片方だけの場合はその値を参考にする。

幼穂形成期の履歴平均には幼穂長1〜2mmの実測を使う。長い幼穂の確認日を形成開始日と同一視しない。幼穂長からの出穂換算は対応品種を明示し、他品種にコシヒカリの表を無断転用しない。

実績平均のマスターへの採用はボタンから編集へ反映し、保存を経て確定する。表示しただけでは変更しない。

## 種籾の準備

温湯殺菌、浸種、催芽は別工程として扱う。

- 温湯殺菌: 60℃・10分・5kgは利用者の設備に合わせた初期参考設定。処理量を一般的な推奨値としない。
- 浸種: 設定水温と積算水温の参考範囲を分けて持つ。一定水温で経過時間から求めた値は、測定した水温の実積算ではなく設定値による推算。
- 催芽: 設定水温と参考時間を持つ。浸種の積算水温を催芽終了の判定に使わない。時間だけで終了を保証せず芽の状態で判断する。

## データ保護

画面から除いた旧資材項目・旧積算温度目標・旧収穫補正値は、保存済みJSONや過去の作業スナップショットから削除しない。新しい現在予測ではそれらの旧補正を使わない。移行時に実績を生成したり、当時不明の品種を現在の設定から補って確定したりしない。

新規の当年生育記録には入力時点の圃場品種を保存する。過去年の記録を新規入力するときには現在品種を補完せず、当時品種不明のまま比較集計から除外する。既存記録の編集でも、保存済み品種は維持し、不明品種は遡及補完しない。

Google Drive連携は今回の対象外。

## 確認記録（2026-11-12）

- 自動回帰テスト `tools/verify_*.js`：96本成功。
- 栽培マスター：閲覧、編集、取消、不正値の保存拒否、保存後の現在予測の変更を360px・390px・1280pxで確認。
- 種子準備：圃場外作業からの任意入力、保存失敗時の入力保持、再読込、編集後も当初設定の保持、実績のマスター採用取消を確認。
- 共通モデル：現地判断と推定の分離、過去予測の保持、幼穂の観測後に長さが増えても形成実測の起点を失わないことを確認。
- 気温：出穂翌日から前日までの確定分だけを実績積算し、出穂当日・今日・未来の値は加えない。
- 共有保存処理：資材の換算、費用、購入計画、取消、保存失敗、過去設定保持の実ブラウザー回帰を360px・390px・1280pxで確認。

本番端末の保存データは操作していない。確認には独立したブラウザーの検証用データを用いた。気象APIとのライブ通信や実際の作期による予測精度の実証とは区別する。
