# 端末外バックアップ対策

## 現在の保存と限界

業務記録と直前退避・更新前退避はブラウザ内に保存される。
端末紛失、故障、サイトデータの削除からは同じ保存領域内の退避だけで復旧できない。
GitHubに公開するアプリのソースコードと、各利用者の記録データは別物である。
利用者のJSONを公開リポジトリへアップロードしてはならない。

## 第1段階

管理画面の先頭に端末外へのJSON保存・共有と従来のJSONダウンロードを配置する。
対応端末ではFile対応のWeb Share APIをユーザー操作で起動する。
未対応、拒否、取消で自動的に別の外部送信やダウンロードは行わない。
共有の成功は保存先への受渡しであり、クラウド保存完了の証明ではない。
共有の取消・失敗ではバックアップ済みの状態に変えない。
ダウンロード時刻も出力開始の記録であり、ファイルの保存完了を保証しない。
JSONには圃場、作業、生育、水管理、機械整備、資材と購入、体系、写真等の既存データが含まれる。
共有先は利用者が選ぶ。同期用アカウント、トークン、送信先は登録しない。
共有用のファイル生成には20MiBの安全上限を設ける。上限を超える場合も、従来のJSONダウンロードで全体を保存できる。

## 第2段階の設計候補（未実装）

利用者または農園アカウントごとに認証された非公開ストレージを設ける。
端末内の即時保存を維持し、オンライン時に送信キューからバックアップを作成する。
保存時刻、端末ID、元リビジョン、チェックサム、件数を記録し、受信確認後にのみ成功表示する。
一定世代を残し、誤削除や破損を即時に全世代へ伝播させない。
別端末での同時編集は最終書込優先で無条件上書きせず、競合として扱う。
復元時は現状のJSONを先に退避し、検査と件数差分を見せてから実行する。
写真、容量、保存期間、認証方法、費用、アカウント削除とデータ持ち出しを決めてからサービスを選ぶ。
サービス契約・認証情報登録・実データのアップロードは別途承認後に行う。

## 技術上の根拠

- https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share
- https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare

共有の対応状況と利用できる保存先は端末によって異なる。
Web ShareのPromise解決時点はプラットフォームによっても異なるため、保存完了とは表示しない。

## 確認（2026-11-06）

共有APIの対応・非対応、取消、拒否、成功、20MiB超過、書出しJSONの互換性を専用検証で確認。
スマホ360px・390pxで管理入口からの共有とダウンロードを操作し、共有では元の保存値が変わらないことを確認。
JSONダウンロード時の変更は既存の出力日時メタデータのみ。実際のファイル内容も検査。
出力開始に失敗した場合と、開始後の日時記録失敗を区別する。
独立コード監査と全80検証スクリプトが成功。
共有先の実際の保存先・クラウド同期完了は実機で利用者が確認する必要がある。
