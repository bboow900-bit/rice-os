# 年産・品種別の収穫成績

## 集計の正本

- 籾摺り後の玄米数量 `millingRecords` を年産・品種で集計する。
- 1俵は60kg。俵/10a = 玄米kg ÷ 60 ÷ 対象面積a × 10。
- 出荷・販売・配布は収穫成績を減らさない。旧品種集計・刈取作業の収量を重ねて加算しない。
- 複数圃場合算の数量を圃場別に推測配分しない。

## 対象面積と年度の確定

- `harvestYearReviews` に年産・品種ごとの対象面積、集計完了、ひとことを保存する。
- 対象面積は、その収量に対応する合計面積を利用者が確認する。同じ圃場の複数ロットで面積を重複加算しない。
- 現在の圃場マスターを過去年の実績面積として自動採用しない。面積未確認は単収未算出とする。
- 明示保存した面積は圃場マスター変更で更新しない。過去面積の訂正は該当年産の編集から行う。
- 集計途中、面積未確認、数量欠測を区別し、0や確定値に置き換えない。
- 完了確認後に収量の登録・数量変更・削除があれば、確認時の根拠と照合して途中集計に戻す。メモだけの変更では完了を解除しない。
- 完了確認が失効した場合、メモ保存だけでは再確定しない。利用者が集計完了を再確認する。

## 振り返り

- 振り返りから年産別の収穫成績を開く。年産を切り替え、品種別に単収、総量、面積、ひとことを表示する。
- 前年比は直前年と比較する。双方の集計が完了し、必要な数値がある場合だけ差を表示する。
- 総収量の差と面積の差を分け、面積変動による増減と単収の増減を混同しない。
- 過去5年の推移は欠測年を残す。集計途中も区別し、未入力を0として描かない。
- メモは実績の背景として表示し、雑草や水管理を増減の原因と自動断定しない。
- 面積・ひとことは成績内で編集。収量不足は年産・品種を引き継いで既存の籾摺り入力へ接続する。

## 保護

- 既存データの初期化・一括書換え・旧収量の自動移行は行わない。
- 新しい確認記録はJSON保存・取込・追加読込の対象に含める。
- 表示、年度切替、取消では保存しない。保存失敗時には入力を保持する。
