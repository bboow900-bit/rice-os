# 収穫時の振り返り

## 実装範囲

稲刈りの作業入力に「収穫時の振り返り（任意）」を追加する。既存の作業ID・対象圃場・日付に保存し、振り返り > 圃場 > 一年の流れ > 稲刈りの詳細で読む。既存の編集・削除・戻る導線を再利用する。

- 田面、機械の走行、残草量、残草の範囲、雑草による作業への影響、雑草名・気づき。
- 今回の収穫面積(a)、今回の収量合計(kg)、収量の測定条件。
- すべて任意。空欄・未確認は、問題なし・雑草なしを意味しない。
- 測定条件と面積がある場合だけ今回の10a換算を表示。乾燥前の籾と乾燥調製後の玄米を同条件として比較しない。

## 保存と互換性

`fieldWorks[].harvestReview` の任意オブジェクトとして追加。既存データの移行・削除・初期化は行わない。省略した更新は既存レビューを保持し、明示的な空欄でその項目だけを消す。不正値では保存全体を中止する。JSON保存・復元も保持する。

グループ登録は1作業に共通の観察と合計収量を持つ。各圃場に合計収量を複製・配分しない。状態が圃場ごとに異なる場合は個別記録にする。対象面積はマスター面積から自動確定しない。

非収穫作業に名称変更した場合も、保存済みレビューは非表示で保持する。稲刈りに戻すと復元する。新規入力・テンプレート・複製では前回の観察を流用しない。

## 水管理の実績

既存 `harvestSnapshots[].water` に落水開始から収穫までの経過日数、出穂から落水開始までの経過日数、落水後の再入水有無を追加。予定だけの落水は実績にしない。入水日は水の動きの入水実績から取得し、中干し開始などを入水とみなさない。

新しい経過日数は開始日との差(同日0日)。旧スナップショットの開始日を含む日数は書き換えず、旧記録と明記する。再入水があれば連続乾燥期間ではないと表示する。雨や田面水の状態が不明なため、落水からの経過日数を乾燥実績日数とは扱わない。

## 第2段階: 稲刈り記録の集計

圃場履歴の収穫振り返り付近に折りたたみで表示する。保存先を追加せず、現時点の作業記録からその圃場・年度の値を読む。既存の結果登録や品種集計に上書き・合算しない。

- 個別圃場の収量は測定条件別に小計を表示する。未確認の測定条件は小計せず、記録の一覧だけに残す。
- 複数圃場にまたがる作業は日付・対象・合計収量を別表示し、個別の小計に加算しない。
- 作業IDが同じものは重複計上しない。非収穫作業・別年度・対象外圃場は除外する。
- 0kgは有効な実測。空欄・不正な値は0kgに変換しない。
- 「記録済み分」であり、年間の全量を確定した表示ではない。面積の重複が判断できないため、年間面積・年間10a収量を勝手に算出しない。
- 元の詳細画面に戻れる導線を再利用し、編集後は保存済みの最新値から表示する。

## 第3段階: 落水後の過去気象

- 収穫スナップショットに任意のweatherを追加。落水開始日から収穫日までの過去気象をArchive APIから保存する。既存記録の移行・削除はしない。
- 当日・未来は取得対象外。平均気温と降水量は別々に取得日数を数え、欠測を0に置き換えない。完全取得済みは固定し、部分取得だけ不足分を補完する。
- 振り返りの収穫詳細に期間、集計値、取得日数、地点、取得日時を表示する。圃場の実測や乾燥日数とは区別する。
- 取得中の削除・日付・圃場・地点変更を拒否。保存時点の最新値を優先し、遅延レスポンスで上書きしない。
