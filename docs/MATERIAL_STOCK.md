# 資材の在庫管理

## 基準

資材の詳細を、製品情報・現在庫・購入・使用・現物確認の共通入口とする。
現物確認は `materials[].stocktakes[]` に追記し、既存の購入や作業履歴を書き換えない。
旧 `remaining`、`ordered`、`used`、`carryover` は保持するが、自動計算へは加算しない。

現在庫 = 直近の確認在庫 + 確認後の実入庫（旧購入は従来方式） - 確認後の使用。
資材IDが同じ記録だけが対象で、同名の別資材や別年度のマスターを自動統合しない。
基準がない資材を0在庫とはみなさず、未登録と表示する。

## 日付と順序

確認日以前に登録済みの購入・使用IDをsnapshotへ保存し、確認数に含む。
同じ日の確認後に追加した別IDの購入・使用は加減算する。
基準以前の履歴を編集・削除しても、現物の確認数を優先する。
確認数に含めた既存IDは、後から日付を変更しても再計上しない。
基準後の記録は、編集・削除に応じて都度再計算する。
未来日の購入・使用はまだ在庫へ反映しない。新方式の購入は、購入日や納品予定日を過ぎても自動入庫しない。

同日内の確認はdate・createdAt・sequence・IDで順序を安定させる。
訂正は新IDで追記し、元の確認をsupersedesIdで参照する。取消はdeletedAtを記録する。
同じ確認日の訂正は元の照合範囲を維持し、その後の購入・使用を取り込まない。
確認を行った時点の計算数量と差をpreviousQuantity・adjustmentとして残す。計算不能ならnullとする。
以前の値は消さず、取り消した確認の解除や同IDの実数上書きを通常の保存APIでは禁止する。

## 使用量と単位

作業のmaterialIdが一致する実績だけを使用量にする。グループ作業は作業1件を1回だけ集計する。
総量と単位を厳密に確認できるものだけを使用量へ反映する。予定・計画は対象外。
袋とkg、Lと袋などは換算しない。面積当たり量を総使用量とは解釈しない。
単位不明・総量不明・不一致があるときは集計保留にし、在庫の確定値を表示しない。
真の負在庫は0へ切り上げず、警告とともに表示する。

## 保存と復元

新規製品と初回確認は、一度の資材保存で同時に確定する。
製品名だけの変更では在庫の再確認を作らない。
在庫履歴のある資材は削除と管理単位変更を禁止する。
JSONはstocktakesとsnapshotの未知属性を保持。統合はstocktakeId単位で既存優先、新IDだけ追加する。
同IDの競合を自動解決する同期ではない。別端末の変更は必要に応じて内容を照合する。
保存失敗時は成功扱いにせず、入力と保存前の記録を保持する。
未指定値undefinedは既存値を消す操作とは扱わない。

## 購入予定と実入庫の分離（2026-11-09 / ver308）

- 新規購入は `deliveryMode: manual` として保存し、`expectedDeliveryDate` は購入ごとの予定日（空欄は未定）とする。
- 製品情報から納品日の入力を外す。旧製品の `deliveryDate` はデータから削除せず、任意の購入へ自動転記もしない。
- 実際の納品は購入詳細から登録し、部分納品は `purchases[].receipts[]` の別IDで残す。
- 在庫計算・確認snapshotの取引IDは購入IDと入庫IDの組み合わせ。購入予定そのものは確認snapshotへ含めない。
- 現在庫 + 未納品数 = 確保予定数。年度購入数は別表示し、現在庫へ再加算しない。単位不一致や現在庫未確定では合計を断定しない。
- 未納品数は年度をまたいでも残る。年度購入費用・数量は購入記録の `season` で区切る。
- 費用は実額優先、なければ単価×数量。0円は有効、未記録は件数を分け、集計可能範囲超過も明示する。
- 既存の方式未指定の購入は従来の在庫計算を維持する。旧購入を自動で未納品へ変更しない。
- 入庫は未来日・過納品・単位不一致を禁止。編集と取消が可能だが、取消履歴を保持し、入庫履歴付き購入の削除・数量縮小・単位変更は禁止する。
- JSON統合は同一購入内の入庫もIDで重複排除し、既存の競合値を優先する。棚卸済みの実数を過去履歴編集で書き換えない。
- 購入一覧の表示照合は資材IDと購入IDの組で行う。別資材に同一購入IDがあるJSONでも納品状況を取り違えない。入庫取消が再試行で成功した場合は、前の失敗表示を解除する。

## 納品待ち・注文取消・計算根拠（ver309）

- 台帳の第三表示「納品待ち」は、手動入庫方式の未納品残だけを一覧化する。年度は注文のseason、分類は同じ資材マスターを参照する。予定日超過は納品予定日が今日より前の場合のみで、未定を超過扱いにしない。
- 注文取消は `purchases[].cancellations[]` に独立ID・日付・数量・理由を保存する。注文数と実入庫を上書きせず、未納品残からだけ引く。取り消しの解除もdeletedAtを残す。
- 入庫数と有効取消数の合計は注文数を超えられない。取消履歴がある購入の削除・数量縮小・単位変更は禁止。JSON統合は取消IDごとに既存優先とする。
- 取消で登録金額を推測減額しない。返金・請求が変わる場合は購入詳細で金額を確認・編集する。年度費用も登録金額を集計していることを明示する。
- 在庫の数字から計算根拠を開く。基準の現物確認と全入庫・使用の採用理由を表示し、元の購入・作業へ接続する。使用量の修正は既存の作業編集へ入り、戻ると元の台帳内訳を維持する。
- 前年比較は同一資材IDの前年seasonに登録された購入だけを表示する。同名の別資材を結合しない。閲覧で履歴を書き換えない。
- 資材一覧の「在庫あり」「在庫なし」「確認が必要」「納品待ち」は表示用の状態で、在庫不足や農作業の指示ではない。
