# 籾摺り後の収量と玄米残量

## 正本と集計

- 籾摺り後の実測収量は `millingRecords` に保存する。
- 既存の `varietyResults` は従来の品種評価・集計記録として残し、在庫には加えない。
- 圃場を指定しない記録は品種集計。複数圃場は合算であり、圃場別には配分しない。
- 年産と品種で収量を合計する。出荷・販売・配布の玄米数量を差し引いて残量を毎回計算する。
- 収量記録そのものは出荷しても変更しない。出荷の編集・削除では残量だけ再計算する。
- 重量の正本はkg。1俵は60kg。残量の袋表示は30kg袋換算であり、現物の袋数ではない。
- 白米は精米による重量変化があるため玄米から同量を差し引かない。数量不足・品種未設定も未反映として区別する。
- 収量より出荷が多い場合、残量をゼロへ丸めず記録の差を表示する。

## 出荷できなかった記録

`shipmentIssues` に日付、年産、品種、理由、対応内容、対応費を保存する。
例えば「籾混入」「全量検査」「100000円」。実際の出荷とは別で、在庫を減らさない。
費用は入力された金額だけ合計する。未入力は無料と同一に扱わない。
これは対応費の記録であり、年間利益や全生産原価を計算する機能ではない。

## 導線

記録を追加 → 収穫・結果 → 籾摺り後の収量。
出荷台帳からも収量・対応費へ到達できる。
指定圃場の一年の流れに籾摺り記録を表示し、同じ記録の編集・削除へ接続する。

## 保護

旧収穫結果、作業、生育、水管理、出荷の自動移行や初期化は行わない。
新コレクションはJSONバックアップと追加読み込みに含める。
読み取り・残量計算だけでは保存しない。失敗・取消で既存記録を変更しない。

## 初期範囲

玄米の年産・品種別残量を扱う。混合圃場の収量配分、精米歩留まり、袋の詰め替え履歴は自動推定しない。
# 確認済みの操作

## 年産別の確認導線

- 管理の「収量・在庫」は履歴を先に表示し、年産・品種ごとの収量、出荷・配布、差引参考在庫を確認する。
- 保存後は保存した年産と記録を表示し、年度変更による見失いを防ぐ。
- 出荷の対応記録も独立した表示年度で絞る。表示年度切替は編集中の入力や保存データを変更しない。
- 出荷台帳から収量へ移動した場合は、戻る操作で出荷台帳、その元画面の順に戻る。下部タブ操作では戻り履歴を破棄する。
- JSON取込確認・保存状況に籾摺り収量と対応記録の件数を表示する。
- 集計範囲を超えた数値は算出不能として扱い、元記録を変更しない。

- `verify_milling_inventory.js` を含む68件の検証に合格。
- 360px・390pxで収量と対応記録の登録、編集、削除、取消、保存失敗時の入力保持を確認。
- 籾混入・全量検査・対応費100,000円を保存しても玄米在庫は変わらないことを確認。
- 圃場の年間履歴から籾摺り詳細・編集へ進み、元の圃場へ戻れることを確認。
- 既存出荷の数量・価格・編集・削除・取消の回帰確認に合格。
