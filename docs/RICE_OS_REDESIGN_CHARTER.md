# 稲作カルテ 再設計方針

更新日: 2026-07-30  
基準版: `rice-os-before-routing-redesign-20260730`

## 目的

稲作カルテを、圃場ごとの実績を記録し、今年の判断と翌年の振り返りに確実につなげるアプリとして維持する。

画面ごとに別の記録を持たせない。記録は一度だけ保存し、ホーム、圃場、カレンダー、振り返りは同じ記録を目的に応じて表示する。

## 絶対ルール

1. 保存済みのJSON、ID、写真、圃場との紐付けを削除・初期化しない。
2. 新しい入力画面を作る場合も、既存の正本コレクションへ保存する。
3. 実績、予定、推定、確認候補、旧記録を同じ扱いにしない。
4. 圃場グループは一括入力の対象選択に使う。実績の所有者は必ず圃場である。
5. どの画面から圃場・記録を開いても、同じ詳細・編集導線へ到達させる。
6. 実装ごとにJSON件数、ID、圃場参照、写真を検査する。
7. ユーザーに見える変更は、スマホUI、データ安全、営農ロジック、独立導線監査を通す。

## 保存データの正本

| 内容 | 正本 | 備考 |
| --- | --- | --- |
| 圃場の固定情報 | `fields` | 品種、面積、土質、グループ、固定メモ、目安日数 |
| 圃場グループ | `fieldGroups` | 圃場側は `fieldGroupId` を参照 |
| 圃場作業 | `fieldWorks` | 一括作業は既存の `fieldIds` を維持 |
| 生育・幼穂・出穂 | `growthLogs` | 幼穂長と出穂確認の正本 |
| 中干し | `dryPeriods` | 開始・終了を持つ水管理実績 |
| 間断灌水・深水・落水 | `irrigations` | 開始・終了を持つ水管理実績 |
| 予定 | `schedules` | 実績とは別。完了した作業への参照だけを持つ |
| 収穫結果・出荷 | `varietyResults` / `shipments` | 圃場結果と品種単位出荷を混同しない |
| 写真 | 各実績レコードの写真項目 | 既存の埋め込み保存を維持 |

## 表示用サービス

画面は保存配列を直接混ぜず、`state` と専用サービスの結果だけを利用する。

- `fieldId` を起点に作業、生育、水管理、写真、予定を取得する。
- 田植日: 田植え作業の最初の実績日を正本とする。圃場側の田植日値は旧データ互換用のキャッシュに留める。
- 生育ステージ: `agro` が実績から返す表示結果。水管理の開始・終了で自動進行させない。
- 水管理の現在地: `resolvedWaterPeriodsFor()` を共通利用する。旧作業由来の記録は、採用されるまで現在値・進捗に混ぜない。

## 下部バーの役割

| 画面 | 役割 | 編集の扱い |
| --- | --- | --- |
| ホーム | 圃場の現在地、今日の予定、今日の記録開始 | 表示中心。カード全体は詳細へ遷移しない |
| 圃場 | 圃場一覧、圃場詳細、圃場設定 | 固定情報だけを圃場設定で編集 |
| カレンダー | 日付ごとの予定・実績、新規記録開始 | 予定だけ編集。実績は記録詳細へ渡す |
| 振り返り | 圃場別の実績、比較、編集、削除 | 実績編集・削除の唯一の入口 |
| お知らせ | 登録済み予定の確認、実施記録への入口 | 予定を確認・実施へ進める |
| 管理 | 共通マスター | JSON、復元、更新は右上のシステム設定 |

## 共通導線

`RiceOS.navigation` を画面遷移の共通入口とする。

- `openField(fieldId, options)`: 共通の圃場詳細を開く。
- `openRecord(kind, recordId, options)`: 作業、生育、水管理、その他の既存編集画面を開く。
- `back()`: 元の画面または直前の圃場・記録文脈へ戻る。画面スクロール位置の復元は次段階で追加する。
- 下部バー: 常に独立したトップ画面へ移動し、詳細スタックを閉じる。選択中タブの再タップは先頭へ戻る。

戻る先の例:

```text
カレンダー
  -> 亀石左下の作業記録
  -> 作業編集
  -> 戻る
  -> カレンダー
```

## 入力と編集

- 新規の作業・生育・水管理: ホームの「今日を記録」またはカレンダーの日付入力から開始する。
- 幼穂と出穂: 分かりやすい専用ボタンを使うが、`growthLogs` へ保存する。
- 実績の編集・削除: 振り返りの共通記録詳細に集約する。
- 中干し、間断灌水、深水、落水: 同じ種類を再度行うと新しい期間として保存する。
- 圃場の削除: 圃場設定だけで行う。

## 段階導入

1. 基準版を凍結し、JSON整合性テストを用意する。
2. 共通ナビゲーションと戻るスタックを追加する。保存形式は変更しない。
3. 圃場詳細の入口を共通化し、圃場設定と実績閲覧を分ける。
4. 記録詳細・編集・削除の入口を振り返りに統一する。
5. ホーム、カレンダー、お知らせを表示・新規入力中心に整理する。
6. 画面固有の表示不具合を共通セレクタ側で修正する。

## 検証チェック

- JSON復元前後で、各コレクション件数と全IDが不変。
- 写真データと `fieldId` / `fieldIds` の参照が不変。
- グループ一括入力が対象圃場にだけ正しく反映される。
- 予定と実績のリンクが編集・削除後も正しい。
- 旧水管理を取り込んでも元作業・写真・メモを失わない。
- ホーム、圃場、カレンダー、振り返りから同一圃場・同一記録に到達できる。
- 360pxから430pxのスマホ幅で横はみ出し、文字重なり、戻れない画面がない。
- PWA公開時はHTML、サービスワーカー、キャッシュ版を同時に更新する。
